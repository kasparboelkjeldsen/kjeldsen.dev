This Blog Was Built by an Agent

A behind-the-scenes look at content modeling, media and publishing — all done through the Umbraco MCP server.

From empty backoffice to published posts

The page you are reading didn't start in the backoffice. It started as a conversation. An AI agent, connected to this site through the Umbraco MCP server, did the entire content build through the same Management API the backoffice itself uses:

  1. Content modeling — element types for the hero, rich text, image and post-list blocks, two block grid data types, and the Blog Front Page and Blog Post document types, each filed in the right folder.

  2. Media — the photos on this site were streamed straight from Unsplash into a media folder with a single batch call.

  3. Content — the front page and both posts, block grid and all, were created and published as structured JSON.

Guardrails, not guesswork

Because the MCP server speaks Umbraco's own API, the agent can't bypass validation, permissions or uSync. Every schema change it made was exported to disk automatically, ready to commit — exactly as if a developer had clicked through the backoffice.

Reading each structure back after writing it means mistakes surface immediately instead of hiding in a half-saved block.

Where humans still matter

The agent is fast, but the conventions were set by people: which folder a document type belongs in, how blocks render, what counts as a Page versus a Repository. MCP doesn't replace those decisions — it makes them executable. Encode your architecture once, and every agent session follows it.

That is the real promise: less clicking, more deciding.
