Building a CMS Site by Conversation

With an MCP server in front of Umbraco, an agent can model, populate and publish content through the same management API the backoffice uses.

This entire site, its document types, data types, media and content, was built by an AI agent talking to a running Umbraco instance over MCP. No clicking through the backoffice, no hand-edited database rows. Just tool calls.

Model first, then content

The agent starts by inspecting what already exists, then creates element types for each block, block grid data types that allow them, and the page types that host them. Every step goes through Umbraco's own management API, so validation, permissions and the folder conventions of the project all still apply.

“The best integration is the one you did not have to write.”

— Every developer, eventually

Content, media and publishing

Once the schema exists, the same server uploads images straight from a URL, creates documents with block grid values, assigns domains and publishes. Read-backs confirm the payload landed the way it was intended.

Why it matters

Editors and developers get a shared, scriptable surface. Repetitive setup becomes a conversation, and the CMS stays the single source of truth. That is MCP doing what it does best: turning a product's capabilities into tools an agent can use safely.
