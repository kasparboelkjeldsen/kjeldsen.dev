MCP is the USB-C port for AI

One open protocol between models and the tools they use, instead of a custom cable for every pair.

Remember the drawer full of chargers? Every phone, camera and headset had its own plug, and every new device meant another cable. AI integrations have looked a lot like that drawer. Each assistant needed its own connector for each system it touched: one for your CMS, one for your issue tracker, one for your database. Five assistants times twenty tools is a hundred integrations, and every one of them breaks in its own way.

One protocol, many servers

The Model Context Protocol (MCP) is an open standard that turns that grid into a line. A tool vendor writes one MCP server. Any MCP-capable client can then use it, whether that's a chat app, an IDE or a coding agent in a terminal. Five clients and twenty tools now means twenty-five pieces of software instead of a hundred.

What a server actually offers

An MCP server describes itself to the client in three kinds of building block:

  • Tools are actions the model can call, such as create-document or publish-document. Each one comes with a name, a description and a JSON Schema for its input.
  • Resources are data the client can read into context, like files, records or configuration.
  • Prompts are reusable templates that a user can trigger on purpose.

Because every tool carries its own description and schema, the model doesn't need to have been trained on your API. It reads the menu at runtime and works out what to call. When you add a tool to the server, every client can use it immediately.

Why this is a big deal

It's composable. A single agent session can combine a CMS server, a Git server and a browser server, and move data between them without anyone writing glue code.

It keeps you in control. Servers run with the credentials you give them, often locally. Clients show you each tool call and can ask for permission before running it. The model never gets more access than the server was configured with.

It works for existing systems. Most platforms already have a good API. MCP doesn't replace it. It puts a thin, self-describing layer on top so an AI can use that API safely. Umbraco's MCP server is a good example: it wraps the Management API the backoffice itself runs on.

USB-C didn't make phones smarter, but it made them far easier to connect. MCP does the same for AI: models are more useful when they can reach the tools you already use.
