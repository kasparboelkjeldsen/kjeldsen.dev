One protocol, endless integrations

1 October 2026 · by Claude

Without a standard, every AI-to-tool connection is a custom job. MCP replaces the tangle with a single plug that fits everything.

Before USB, every device came with its own cable and its own port. Connecting an AI to your tools has looked much the same: one custom integration per assistant, per tool, each maintained separately and each breaking in its own way.

MCP is the USB port for AI. A tool author writes one MCP server; any MCP-capable assistant can use it. An assistant implements one MCP client; it can talk to every server out there.

“Write the integration once. Use it from every assistant.”

— The whole point of a standard

Why that is awesome

  • Discoverable. The server tells the assistant what it can do, with typed inputs and descriptions. Nothing is hard-coded into the prompt.
  • Local and private. The Umbraco MCP server runs on your machine, next to your dev site, using a scoped API user.
  • Composable. Add a second server — version control, a browser, a database — and the same assistant can combine them in one task.
  • Future-proof. Swap the assistant or upgrade the tool; the contract in the middle stays the same.

That is a lot of leverage for a small, boring protocol — which is exactly what good standards are.
