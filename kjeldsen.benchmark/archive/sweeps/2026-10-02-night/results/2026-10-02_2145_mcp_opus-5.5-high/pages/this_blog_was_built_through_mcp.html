This Blog Was Built Through MCP

No clicking through the backoffice. An agent, a CMS and a protocol in between.

Photo: Alina Grubnyak / Unsplash

Every page on this site came out of a conversation. An AI agent connected to the Umbraco MCP server, read the project's conventions, and then did the work: it created the element types and block grid data types, filed them in the right folders, imported the photos into the media library, and wrote and published the posts you're reading.

What the agent actually did

  1. Content modeling. It created five block element types (hero, rich text, image, quote and blog post list), two block grid data types, and the Blog Front Page and Blog Post page types, each with a template.

  2. Media. It imported Unsplash photos from a local folder straight into a Blog media folder.

  3. Content. It composed each page as a block grid value and published it, then read the document back to check the structure took.

  4. Routing. It assigned the blog a domain so it answers on /.

Why this is awesome

Structure, not just text. A chatbot that writes copy still leaves you to paste it in. An agent with MCP works with the CMS's real model: document types, block grids, media pickers. What it produces is proper structured content that editors can keep working on in the backoffice.

Conventions are respected. Because the agent goes through the same management API as the backoffice, the CMS's own rules still apply. Here, data types end up in the right folders, uSync exports every change, and nothing bypasses validation.

It is all local. The MCP server runs next to the site on a developer machine. It uses a dedicated API user that only exists in development, and it can only read media from an allow-listed folder.

Tedious becomes conversational. “Add a quote block to the post grid.” “Import these ten photos into a folder.” “Publish everything under Blog.” These used to take dozens of clicks each. Now they take one sentence.

MCP doesn't replace editors or developers. It removes the busywork between having an idea and seeing it on the page.
