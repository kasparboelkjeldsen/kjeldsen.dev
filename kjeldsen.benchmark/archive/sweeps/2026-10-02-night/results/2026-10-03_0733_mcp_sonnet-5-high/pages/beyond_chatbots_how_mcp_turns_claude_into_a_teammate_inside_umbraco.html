Beyond Chatbots: How MCP Turns Claude into a Teammate Inside Umbraco

October 2, 2026

Built by MCP calls, not by hand

Everything on this site — the block types, the data types, the pages you're reading right now — was created through calls to Umbraco's MCP server: create-element-type, create-data-type, create-document, publish-document. No backoffice clicking, no custom migration scripts. That's the practical meaning of 'MCP is awesome': it's not a demo, it's the actual authoring path.

The CMS becomes a tool, not a UI to work around

Traditionally, automating content work means screen-scraping a backoffice or writing one-off scripts against an internal API. An MCP server flips that: the CMS's own operations — create a document type, move it into a folder, publish a page — are exposed as typed, discoverable tools. The agent doesn't need a bespoke adapter for Umbraco specifically; it needs to speak MCP, and Umbraco already does.

“We didn't write a line of migration code for this blog. We described the content model, and the server built it.”

— This project, probably

What this means for teams

An editor can ask an agent to draft a landing page from a brief; a developer can ask it to scaffold a document type from a spec. Because the MCP server speaks Umbraco's real structural rules — folders, compositions, block grid shapes — the result isn't a pile of guesswork, it's content and types indistinguishable from what a person would have built by hand.
