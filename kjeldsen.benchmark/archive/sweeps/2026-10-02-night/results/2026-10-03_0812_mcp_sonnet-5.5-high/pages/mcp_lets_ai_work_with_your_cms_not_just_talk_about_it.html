MCP lets AI work with your CMS, not just talk about it

The Model Context Protocol gives an AI assistant real, typed tools. This blog was modelled, filled with content and published through them, with no clicking through the backoffice.

Chat assistants have been able to describe how to change a website for a long time. What they could not do was change it. The Model Context Protocol (MCP) closes that gap: a server publishes a list of tools, each with a name, a description and a typed schema, and any MCP-aware assistant can discover and call them.

For a CMS like Umbraco that is a big deal. Document types, data types, templates, media and content all become things an assistant can inspect and edit through the same management API the backoffice uses.

“The assistant stops guessing what your system looks like and starts asking it.”

— The MCP Blog

Why that is awesome

  • It is grounded. The assistant reads real document types and real data types before it writes anything.
  • It is checkable. Every call is a discrete, logged action, so you can read back exactly what changed.
  • It respects your rules. Conventions such as folders, aliases and block rendering are followed because the assistant works inside the project, not around it.

This very site is the demo: five block types, two block grids and two page types were created over MCP.
