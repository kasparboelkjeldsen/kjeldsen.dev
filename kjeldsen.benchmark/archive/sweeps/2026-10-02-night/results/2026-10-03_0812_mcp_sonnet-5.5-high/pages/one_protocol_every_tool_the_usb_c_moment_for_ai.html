One protocol, every tool: the USB-C moment for AI

Before MCP every assistant needed a bespoke integration for every tool. One open standard turns that N-by-M problem into plug and play.

Remember when every phone had its own charger? Integrating an AI assistant with your tools used to be the same story: one custom connector per assistant, per tool. Ten assistants and ten tools meant a hundred integrations, all slightly different and all slowly rotting.

MCP replaces that with a single, open contract. A tool is wrapped once as an MCP server, and every MCP client can use it. Build once, plug in anywhere.

“Write the integration once. Every assistant that speaks MCP can use it.”

— The MCP Blog

What you get in practice

  • Portability. Swap assistants without rewriting your tooling.
  • Discoverability. Tools describe themselves, so a client learns what is possible at runtime.
  • Local control. A server can run on your own machine, with your own credentials and a scope you choose, as this project's .mcp.json does.

That is why MCP feels less like a feature and more like infrastructure: it is the boring, standard plug that makes everything else work together.
