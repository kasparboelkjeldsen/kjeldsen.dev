Your CMS, now with a conversation

This blog was built by an AI agent working through Umbraco's MCP server: content model, media, posts and all. Here's what that looks like, and why it's more than a party trick.

The usual way to stand up a site in a CMS is a long afternoon of clicking: create a document type, add properties, configure a block grid, upload images, write content, publish, repeat. It's not hard work, but it's a lot of it.

The site you're reading took a different route. An AI agent was given a short brief ("a blog with a front page and two posts, built with blocks") and access to Umbraco's MCP server. Everything else happened through tool calls.

What the agent actually did

  1. Modelled the content. It created element types for a hero, rich text, images, quotes and a post list, then filed them into the project's Blocks folder. It created an SEO composition and two page types, and wired them together with block grid data types.
  2. Imported media. It pulled photos from a local folder into the media library, inside a folder as the house rules require.
  3. Wrote and published content. The front page and both posts were created as structured block grid JSON, read back to verify, then published.

It follows the rules

The interesting part isn't speed. It's that the agent works inside the CMS's own model. It uses the same document types, data types and validation an editor would. Nothing gets bolted on from outside, so nothing gets out of sync.

Because the project's conventions are written down (where each kind of type lives, how aliases are named, how blocks render), the agent can follow them just like a new team member would. It does it on the first try, every time.

“The point isn't that the machine clicks faster. It's that the CMS becomes something you can talk to.”

The MCP Blog

Where this goes next

Scaffolding a demo blog is the easy case. The same tools cover the jobs that eat real editorial time: restructuring a content model across hundreds of pages, migrating copy from an old site, auditing every page for a missing meta description, or translating a section into a new language. These tasks are tedious for people and easy to describe to an agent.

And because it's MCP, none of it is tied to a single assistant. Any MCP client can drive the same server, with the same permissions, against the same management API your backoffice already uses.

So: MCP is awesome. Not because it's magic, but because it gives your existing tools a front door that AI can walk through, without anyone having to build a new house.
