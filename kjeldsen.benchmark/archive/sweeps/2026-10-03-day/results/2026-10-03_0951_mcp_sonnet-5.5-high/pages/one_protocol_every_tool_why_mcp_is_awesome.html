One Protocol, Every Tool: Why MCP Is Awesome

Before MCP, every AI integration was a bespoke adapter. The Model Context Protocol replaces that tangle with one open standard, and the difference is hard to overstate.

The end of one-off integrations

Connecting an AI assistant to a system used to mean writing a custom plugin for that exact assistant and that exact system. Ten assistants and ten systems meant a hundred adapters, each with its own quirks and its own way of breaking.

The Model Context Protocol, or MCP, flips that around. A system describes what it can do once, as a set of tools with typed inputs and outputs, and any MCP-aware client can discover and use them. You build the integration once and every client benefits.

Discoverable by design

An MCP server tells the client what it offers. There is no documentation to paste into a prompt and no endpoint list to memorise: the assistant asks the server for its tools, reads their schemas, and works out how to call them.

That is how this very post got into the CMS. The assistant listed the document types, looked up the data types it needed, created the content and published it, all through tools the Umbraco MCP server advertised about itself.

  • Typed inputs mean fewer malformed calls.
  • Self-describing tools mean no stale documentation.
  • An open standard means no vendor lock-in.

“Build the integration once, and every client gets it for free.”

— The whole point of MCP
