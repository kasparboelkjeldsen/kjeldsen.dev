MCP is the USB-C port for AI

One open protocol, any model, any tool. Here is why the Model Context Protocol is the most important plumbing in AI right now.

Photo by Hal Gatewood on Unsplash

The N×M problem

Before MCP, connecting an AI assistant to something useful — a database, a ticket tracker, a CMS — meant writing a custom integration. Then doing it again for the next assistant. Ten assistants and ten tools meant a hundred brittle adapters, each with its own auth, its own schema, and its own bugs.

The Model Context Protocol collapses that grid. A tool vendor writes one MCP server. An AI host implements one MCP client. Everything that speaks the protocol can talk to everything else. N×M becomes N+M.

Three simple primitives

  • Tools — actions the model can call, described with a JSON schema.
  • Resources — data the host can read into context.
  • Prompts — reusable, parameterised templates a user can pick.

That is genuinely most of it. Small surface area, easy to implement, easy to reason about.

Why it matters

Because MCP is open and transport-agnostic, it works the same over a local stdio process on your laptop as it does over HTTP in the cloud. Your assistant doesn't care whether it is talking to GitHub, Postgres or Umbraco — it discovers the tools, reads their schemas and gets on with the job.

For vendors, that means one integration reaches every MCP-capable assistant. For developers, it means the assistant you already use can suddenly do real work in the systems you already have. And for everyone, it means less glue code and more time spent on the thing you actually wanted to build.
