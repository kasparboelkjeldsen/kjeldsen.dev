This blog was built by an AI over MCP

No copy-paste into the backoffice. No custom import script. Just an assistant, a protocol and a CMS that speaks it.

Photo by Edge2Edge Media on Unsplash

From prompt to published

This site started as an empty Umbraco install with a single WWW node. An AI assistant connected to the Umbraco MCP server then:

  1. Created five block element types — Hero, Rich Text, Image, Quote and Blog Post List — and filed them in the Blocks folder.
  2. Configured two Block Grid data types and the Blog Front Page and Blog Post document types.
  3. Imported Unsplash photos into a media folder.
  4. Wrote, structured and published the front page and both posts — block by block.

Every one of those steps is an ordinary management API call, exposed as an MCP tool the assistant can discover and use.

Why this is awesome

It respects your model. The assistant isn't pasting HTML into a single text field. It reads the document types, discovers which blocks are allowed where, and writes structured content that editors can keep working with in the backoffice.

It respects your rules. Folders, aliases, media organisation — the same conventions a human developer follows apply to the AI, because it goes through the same API.

It is local and safe. The MCP server runs next to your dev site, talks to it with a scoped API user, and only reads media from folders you explicitly allow.
