Why MCP is awesome: one protocol, every tool

The Model Context Protocol gives AI agents one standard way to talk to any tool. Here is why that small idea changes how we build software.

One protocol instead of a hundred integrations

Every tool an AI agent might want to use has its own API, its own authentication quirks and its own idea of what a "document" is. Before the Model Context Protocol (MCP), connecting an agent to a CMS, a database or a ticketing system meant writing a bespoke adapter for each one, and then writing it again for the next agent.

MCP replaces that N-times-M problem with a single contract. A server describes the tools it offers, with names, descriptions and JSON schemas for their inputs. A client, usually an AI agent, discovers those tools at runtime and calls them. Any client can talk to any server. Build the integration once and every agent gets it.

“Think of MCP like a USB-C port for AI applications. Just as USB-C provides a standardized way to connect your devices to various peripherals, MCP provides a standardized way to connect AI models to different data sources and tools.”

— The MCP documentation

Tools that describe themselves

The part that makes MCP genuinely useful for agents is that the tool descriptions are the documentation. When the Umbraco MCP server exposes a tool for creating a document type, its schema tells the agent exactly which fields exist, which are required and what shape the values take. There is no manual to read and no guesswork about parameter names. The agent reads the schema, builds the call and moves on.

Local, scoped and auditable

An MCP server runs where you want it to run. The server behind this blog runs on the developer's machine, speaks to a local Umbraco instance over its management API and is limited to a handful of tool collections and one folder of images. Everything the agent does goes through the same API the backoffice uses, so the same permissions, validation and audit log apply.

Why it matters

Agents are only as capable as the tools they can reach. MCP turns "can the model do this?" into "is there a server for this?", and the answer is increasingly yes. That shift, from bespoke glue code to a shared protocol, is what makes MCP awesome.
