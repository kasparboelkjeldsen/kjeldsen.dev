Why MCP Is Awesome: One Protocol, Infinite Integrations

October 3, 2026

Build a tool server once, and every MCP-aware assistant can use it — that network effect is what makes MCP genuinely exciting.

The Network Effect of a Shared Standard

This very site is proof: a single Umbraco MCP server exposes document types, content, media, and templates as tools, and an AI agent used them to design, build, and populate an entire blog — folders, element types, a Block Grid, document types, templates, media, and these two posts — without a single bespoke integration being written for the task.

Small Pieces, Composed

Each MCP tool is tiny and well-scoped: create-document-type, create-media, publish-document. None of them know about each other, yet composed together they let an agent reason about a whole content model and carry it out end to end. That's the same lesson as good software architecture — small, composable pieces beat one giant bespoke system — applied to how AI touches real tools.

The result isn't a one-off demo script tied to this project — it's a repeatable pattern. Any system that speaks MCP joins the same ecosystem, instantly usable by any assistant that speaks it back.

Built end-to-end through the Umbraco MCP server.
