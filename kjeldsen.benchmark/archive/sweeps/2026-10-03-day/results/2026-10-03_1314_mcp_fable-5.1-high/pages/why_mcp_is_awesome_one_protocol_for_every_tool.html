Why MCP is awesome: one protocol for every tool

28 September 2026 · Claude

Before MCP, every AI integration was a bespoke adapter. The Model Context Protocol replaces that pile of glue code with one open standard that any assistant and any tool can speak.

Every few years the software world agrees on a plug. USB did it for peripherals, HTTP did it for documents, and the Model Context Protocol (MCP) is doing it for AI assistants and the tools they use. Before MCP, connecting a language model to a CMS, a database or a ticketing system meant writing a one-off adapter for that exact pair. Swap the model and you rewrote the adapter. Swap the tool and you rewrote it again.

MCP breaks that N-times-M problem. A tool exposes itself once as an MCP server. An assistant implements the client side once. From then on, any client can use any server, and nobody has to write glue code again.

Three things that make it click

1. Tools describe themselves

An MCP server publishes a list of tools, each with a name, a description and a JSON schema for its arguments. The assistant reads that list at runtime, so adding a capability to a server is enough to make it available to every client. There is no SDK to update and no prompt to rewrite.

2. It is transport-agnostic

MCP runs over standard input and output for local processes and over HTTP for remote services. The same server code works whether an agent runs it on a laptop or talks to it across the network.

3. Permissions stay with the host

The protocol separates what a tool can do from whether it may do it right now. The client decides which calls to allow, which to confirm with a human, and which to refuse. That makes it practical to hand an agent real write access to a production system, because the guard rails live outside the model.

“The best integration is the one nobody had to write.”

— Every developer who has maintained a custom API adapter

Why it matters for a CMS

A content management system is a perfect fit for MCP because it is already a well-defined API with clear nouns: document types, data types, media, templates and documents. Expose those as tools and an assistant can model a site, fill it with content and publish it, while the CMS keeps enforcing validation, permissions and audit logs exactly as it does for a human editor.
